# Implementation Plan: Workout History & Weight Tracking Pagination with Date Range Filtering

**Branch**: `006-pagination-date-filter` | **Date**: 2026-06-02 | **Spec**: [spec.md](spec.md)

**Input**: Feature specification from `specs/006-pagination-date-filter/spec.md`

## Summary

Add server-side pagination and date range filtering to the Workout History and Weight Tracking pages. The server functions already implement SQL-side LIMIT/OFFSET pagination; the remaining work is entirely UI-side: replace the Apply-button date filter with auto-apply + 500 ms debounce, replace inline error text with a warning icon + tooltip, replace simple Prev/Next buttons with a shadcn `Pagination` component (numbered pages + ellipsis), and move all filter state into URL search params via TanStack Router's `validateSearch`. A `useDebounce` hook and a `Pagination` UI component must be created.

## Implementation Design

### 1. `src/hooks/use-debounce.ts` (NEW)

```typescript
import { useState, useEffect } from "react"

export function useDebounce<T>(value: T, delay: number): T {
  const [debounced, setDebounced] = useState(value)
  useEffect(() => {
    const id = setTimeout(() => setDebounced(value), delay)
    return () => clearTimeout(id)
  }, [value, delay])
  return debounced
}
```

Used in both page components to debounce the derived date range before it is synced to URL params.

### 2. `src/components/ui/pagination.tsx` (NEW)

A shadcn-style component built on the existing `Button` + `cn` primitives.

**Props**:
```typescript
interface PaginationProps {
  page: number
  totalPages: number
  onPageChange: (page: number) => void
}
```

**Render logic**:
- If `totalPages <= 1`: render nothing (FR-012).
- Show prev arrow (disabled when `page === 1`).
- Show up to 7 page slots using the standard ellipsis algorithm:
  - Always show pages 1 and `totalPages`.
  - Always show `page - 1`, `page`, `page + 1` (clamped to valid range).
  - Insert `…` where gaps exist between shown pages.
- Show next arrow (disabled when `page === totalPages`).

**Ellipsis algorithm** (produces at most 7 rendered slots):
```
pages to show = unique sorted set of:
  [1, max(1, page-1), page, min(totalPages, page+1), totalPages]
then insert '…' between non-consecutive numbers.
```

**Styling**: Matches existing `Button` variant styles. Active page uses `variant="default"`; inactive pages use `variant="outline"`.

### 3. Workout History Route — `index.tsx` (MODIFIED)

**Route declaration changes**:

```typescript

  validateSearch: (raw) => ({
    page: Math.max(1, Number(raw.page) || 1),
    from: typeof raw.from === "string" && raw.from ? raw.from : defaultStartDate(),

  loader: async ({ context, deps }) => {
    await context.queryClient.ensureQueryData(

    )
  },
  component: WorkoutHistoryPage,

```

**Component changes**:

Remove:

- Apply `<Button>`

Add:

## Risk Notes

- **`validateSearch` and `loaderDeps` are critical**: Without `loaderDeps`, the route loader only fires once and the `useSuspenseQuery` handles all subsequent fetches client-side. This is acceptable but means the first paint on a shared URL does not SSR the filtered data. If SSR fidelity for filtered URLs is required, `loaderDeps` is essential.
- **Debounce + Suspense**: `useSuspenseQuery` will suspend on cache misses. During the 500 ms debounce window, the stale data from the previous valid range remains visible. This is intentional and good UX — no empty flash.
- **Back button and page history**: Each URL navigation pushes a new history entry. Rapidly changing dates will pollute history. Mitigate by using `replace: true` in `navigate` for date-range changes (not page changes, where push is the correct UX).
